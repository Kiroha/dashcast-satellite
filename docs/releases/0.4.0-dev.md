# DashCast Satellite 0.4.0-dev — Connection and device identity

Install this APK on the Tbox and **DashCast 1.9.13-beta** on the vehicle. Update both
without uninstalling; the saved profile and signing identities remain compatible.
Application version code is **5**. This is still a guidance-only test build.

- Fix the production WebSocket upgrade rejection caused by an explicitly empty
  subprotocol list. Pinned TLS, hello/welcome authentication and LAN socket binding
  remain mandatory.
- Prefer the selected LAN's gateway and local-subnet addresses, remember a working
  endpoint during the service session, and apply reconnect backoff after trying the
  bounded candidate list. A default route alone does not establish a local-subnet match.
- Show the saved DashCast ID and addresses, plus this Satellite's model label and
  random installation ID. DashCast shows that device after authentication and labels
  previous connections as history. A saved pairing is distinct from an open connection.
- Show the attempted car address and the last fixed failure explanation. Distinguish
  connection timeout, authentication timeout, transient TLS errors and certificate
  rejection without exposing raw server or exception text.
- Guide Android 13+ users to App info → ⋮ → Allow restricted settings when notification
  access is blocked. The app cannot grant access itself. After allowing restricted
  settings, return and enable notification access, then enable **Use satellite guidance**
  in DashCast and start a route.

Optional device metadata is additive to the reviewed v1 contract. It is display
information authenticated by the existing shared pairing token, not a new per-device
credential. Notification images, route content and pairing secrets are not added to
diagnostics or identity labels.

Validation includes **131 unit tests**, actual production transport over pinned TLS,
WebSocket upgrade and hello/welcome, connection/authentication deadlines and socket
cancellation, endpoint ordering, identity lifecycle and Android settings UI. Debug
lint reports zero issues, assembly and pinned-contract verification pass. Checksums
accompany the local APK. Physical guidance and
reconnection validation on the Carlinkit remain pending.
