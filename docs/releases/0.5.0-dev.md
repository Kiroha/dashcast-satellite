# DashCast Satellite 0.5.0-dev — IPv4 hotspot recovery

Install this APK on the Tbox and **DashCast 1.9.14-beta** on the vehicle without
uninstalling either app. Application version code is **6**. This is a guidance-only
test build; physical guidance and reconnection acceptance remain pending.

- Use local IPv4 addresses for automatic/manual code pairing and persistent WSS.
  Previous v1 profiles containing IPv6 remain readable, but IPv6 addresses are
  excluded from connection attempts and the saved-address display.
- Try the selected Wi-Fi/Ethernet LAN's current IPv4 gateway first, even when a
  hotspot restart changed its address since pairing. The saved certificate pin
  and token still authenticate that endpoint; a different certificate is rejected
  before hello. Cellular, VPN and process-default routing are not used for these sockets.
- Retain bounded endpoint cycles, reconnect backoff, latest-value guidance and
  actual source age. If neither the selected LAN nor the saved profile provides
  an IPv4 endpoint, show an explicit unavailable-address explanation.
- The matching receiver exports IPv4 candidates and keeps preparation failures
  visible with **Try again**. Retry creates a new window; hiding a pending or ready
  window preserves its original two-minute deadline.

Automated regressions exercise the production transport over pinned TLS, an
unadvertised but LAN-provided gateway, rejection of a different gateway certificate,
IPv6 exclusion, legacy profile parsing and notification-source fixtures. Receiver
tests exercise the actual Pair device click, failed preparation/bind/start requests,
background preparation and stale receiver/listener callbacks.

Independent verification: **138 unit tests in 22 suites**, zero debug lint issues,
successful debug assembly and verified protocol/fixture pins. The matching receiver
passes **989 tests in 185 suites**, release lint and signed release assembly.

User feedback on October 11 confirms notification access is granted on Android 15
and reports repeated connection timeouts. It does not establish successful route
observation or physical guidance. The vehicle's original preparation failure still
requires a fixed diagnostic state or sanitized startup logs to identify its cause.
