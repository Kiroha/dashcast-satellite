# DashSat 0.6.0-dev — Manual OTA updates

Application version code: **7**. This remains a guidance-only development build.
Install this first OTA-capable APK manually on the Tbox without uninstalling.
Existing pairing, settings and the independent Satellite signing identity are preserved.

- Rename the application to **DashSat**. Existing package identity, pairing and signing
  remain compatible. New release assets use the DashSat name; the updater also accepts
  the exact legacy DashCast-Satellite filenames and rejects ambiguous APK assets.
- Open **Updates** to check public GitHub releases on demand, read release notes,
  download a compatible APK and open Android's update installer.
- Development installations select development APKs, including prereleases. Production
  installations select production APKs from stable releases. Versions are compared
  numerically; publication order and GitHub's latest stable release do not choose the update.
- Downloads use the ordinary Internet connection. Guidance remains on its existing LAN
  connection; the updater does not bind the process or change SIM/Wi-Fi routing.
- Check bounded HTTPS download size and SHA-256, exact package and release version,
  increasing Android version code, minimum Android version, build channel and the
  installed application's current APK signing certificate before installation.
- Allow installation from DashSat when Android requests it, then return and tap
  **Install update** again. Android always asks for installation consent. Setup should
  be completed while parked; installation restarts the application normally.
- Retry errors manually. Rotation retains the active operation; closing Updates or pressing Back cancels it and discards staged downloads. No background polling or silent
  installation is added.

Physical installation, Android 15 permission settings and guidance recovery after
update on the Carlinkit Tbox remain pending hardware validation.

Validation: **154 unit/UI tests across 25 suites**, zero debug lint issues, debug
assembly and both pinned protocol checks pass. OTA-specific tests cover numeric
release/channel selection, APK trust policy, modified/truncated bytes, actual screen
check/error/retry and recreation, API 26/35 installation-source consent, one read-only
installer URI grant and cancellation cleanup. Android's actual package replacement
and Tbox firmware behavior still require the physical tests listed above.
