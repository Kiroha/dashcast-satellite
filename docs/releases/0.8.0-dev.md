# DashSat 0.8.0-dev — Share first, then return to DashCast

Application version code: **9**. Video sharing can now start while the DashCast viewer is hidden.
This supports a Carlinkit accessed through CarPlay on the same central screen as DashCast.
Use [DashCast 1.9.20-beta](https://github.com/Kiroha/byd-dashcast/releases/tag/v1.9.20-beta)
with its older-WebView startup fix; no receiver update is required for this sharing flow.

Install over 0.7.0-dev without uninstalling, manually or through **Updates**. Package, independent
signing key, pairing, guidance and protocol v1 remain compatible.

## Setup while parked

1. Start the DashSat connection on the Tbox, choose an app, then **Start video sharing**.
2. Approve Android's sharing dialog. On Android 14+, choose the same app in Android's own chooser;
   Android decides the captured app. Earlier versions mirror the entire box display.
3. The selected app can open while DashSat shows **Screen sharing active · waiting for DashCast**.
4. Leave CarPlay and open **Preview received map** in DashCast. The video connection starts when
   the viewer becomes ready. Use the existing cluster route after checking the preview.
5. Stop from DashSat or the ongoing sharing notification, including while waiting for a viewer.

Closing/hiding the viewer pauses transmission and releases its decoder and the sender's peer/encoder.
The same continuously authorized foreground capture session waits and resumes with a fresh
negotiation when the viewer returns. MediaProjection is acquired once; its VirtualDisplay is created
at most once and resized in place. Initial waiting does not initialize native video resources. Later
waiting suppresses frame forwarding, static refresh, encoding, ICE and native stats polling; the box
may still compose into its retained capture display.

Stop, Android revocation, device lock/screen-off, hidden/paused shared source content, control/LAN
loss or a fatal video error ends sharing. New Android consent is required after that; there is no
unattended capture restart. Guidance remains separate. Sharing can include personal information;
protected content can be blank. No audio, remote input or invisible independent app display is added.

The app still runs and hardware-encodes on the box, with up to 960×540, 15 fps and 1.5 Mbps over
local WebRTC UDP. DashCast still decodes/displays the stream. Actual vehicle video, hardware decoder
use, latency and CPU/GPU savings require parked vehicle tests and are not established by local checks.
