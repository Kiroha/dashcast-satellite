# DashSat 0.9.5-dev

Adds a bounded H.264 startup recovery: the existing hardware encoder may receive up to three extra
keyframe requests near 2, 5 and 9 seconds after the peer first connects. Requests stop after 12 seconds;
late frames do not cause a catchup burst. Existing native KEY and EMPTY/drop requests are preserved.
There is no periodic keyframe loop, extra polling, software encoding fallback or codec/profile change.

Each viewer attempt owns its factory, source, track and immutable recovery ticket. A single authorized
Android projection, display and texture helper remain active across temporary source/viewer pauses.
Old attempts cannot request recovery after source loss, viewer closure, control replacement or stop.

This targets a possible incomplete startup keyframe observed in the October 16 16:47 report; that
report showed RTP arrival, zero decoded frames and only one sender keyframe. It does not prove that
packet loss caused the failure or that this recovery fixes the vehicle. The existing manual diagnostics
show actual encoded keyframes; a request alone does not prove that hardware produced a keyframe.

Validated with 251 JVM tests across 41 suites, including encoder API forwarding, immutable peer
ownership, source/viewer epoch changes, partial initialization and teardown failure handling. Protocol
pins and the WebRTC archive checksum are unchanged and verified; debug assembly and lint passed
(zero lint issues). Vehicle image and CPU/GPU validation remain pending.
