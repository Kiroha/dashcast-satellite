# DashSat 0.9.7-dev

Corrects hardware H264 profile configuration after a Tbox report showed High-profile video while
DashCast had negotiated Constrained Baseline. DashSat now explicitly configures the supported
hardware Baseline profile and level 3.1, including encoder restarts, and checks emitted SPS profile
bytes before sending encoded images. Incompatible or unobservable startup output stops sharing
with an explicit local status instead of continuing to send it.

The existing SDK selects the hardware codec. There is no native library replacement, software
encoder fallback, system WebView change, receiver change or pairing reset. Guidance remains an
independent feature. Compatibility checks continue after the startup diagnostic window; the manual
diagnostic payload and its finite observation budget remain unchanged.

Use with your current DashCast 1.9.41-beta or later. Install this update, start a new sharing session
and keep the DashCast viewer visible for 20 seconds while parked. If the image remains black, send
diagnostics from DashSat, wait for confirmation and create a DashCast bug report.

Real Tbox hardware output, the first decoded image, latency and vehicle CPU/GPU savings remain
physical validation gates. Source tests and final artifact checks are documented separately.

Validation: 283 unit/protocol/transport tests pass across 45 suites, debug lint reports zero issues,
debug assembly passes and pinned protocol/pairing fixtures are verified. Independent checks and
exact APK metadata/signing are recorded with the frozen release artifacts.
