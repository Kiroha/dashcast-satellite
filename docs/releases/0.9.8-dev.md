# DashSat 0.9.8-dev

Adds **Test video compatibility**, an explicit synthetic reference test for the unresolved black
video on some vehicle WebViews. Requires DashCast 1.9.44-beta or a receiver advertising the complete
reference-test capability. Normal sharing and testing cannot run together.

While parked, select an app, choose the test, read the explanation and accept fresh Android
screen-sharing consent. Leave the selected shared app open on the Tbox, then return to DashCast and
open the viewer. No app images are transmitted during this test: two known 960×452 H.264 Constrained
Baseline images alternate, visibly marked TEST PATTERN. The same native WebRTC packetizer, local
DTLS transport and receiver are used. No software encoding fallback or replacement vehicle WebView
is installed. Reference mode does not depend on a working hardware encoder.

The test needs new platform capture callbacks; a static cached texture cannot manufacture test
frames. It sends at most five frames per second and stops after 15 seconds from the first reference
negotiation, or 60 seconds after consent, even without a viewer or any frames. Reconnecting does not
renew the limits. A notification Stop action remains available. Normal sharing afterward requires a
new consent. Send diagnostics to DashCast and generate the bug report after the test.

Diagnostics label reference/capture attempts, including receiver-only histories. Older diagnostics
formats remain unchanged and omit reference attempts rather than mislabeling them as capture.

This release does not claim to fix the black video or prove hardware decoding, ABRP compatibility,
low latency or vehicle CPU/GPU savings. Those require actual vehicle evidence.
